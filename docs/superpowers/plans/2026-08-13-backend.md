# Backend Implementation Plan — Marram Wedding Studio

> **Superseded:** Supabase was swapped for Neon + Drizzle + NextAuth v5 after implementation (no free Supabase project slots available). The task breakdown and file-by-file shape below still describes the intent accurately — same 4 seams, same tables — but every Supabase-specific snippet (`@supabase/ssr` clients, RLS policies, PostgREST queries) was replaced. See the actual code for the current implementation: `src/lib/auth.ts` (NextAuth config), `src/lib/db/schema.ts` (Drizzle schema), `src/lib/db/client.ts` (Neon client), `src/proxy.ts` (session guard). One structural difference: Neon has no client-safe query layer, so browser-side calls that used to hit Supabase directly (storage sync, lead capture) now route through API routes (`/api/user-state`, `/api/lead`, `/api/inquiry`) instead.

## Context

The frontend is complete and frozen. All 15 audit findings are fixed. The approved backend design spec (`docs/superpowers/specs/2026-08-13-backend-design.md`) describes wiring Supabase + Resend behind four existing integration seams so the site works like a real production app — zero cost, free tiers only.

The plan was composed in the previous context but the Write never executed before compaction. This is the write.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire a full Supabase + Resend backend behind the existing Marram Wedding Studio frontend so leads land in a database, couples can create accounts with planning data synced across devices, published wedding sites work from any browser, RSVPs send real emails, and analytics report to Vercel.

**Architecture:** Supabase provides auth (magic link + Google OAuth), Postgres with RLS, and session management via `@supabase/ssr` cookies. Four existing integration seams in the codebase (`repository.ts`, `storage.ts`, `/w/[slug]`, analytics) are swapped for real implementations. Resend handles all transactional email. No component changes except `CoupleSite.tsx` (RSVP form) and `PublishedSite.tsx` (publish trigger).

**Tech Stack:** Next.js 16 App Router, Supabase JS v2, `@supabase/ssr`, Resend SDK, `@vercel/analytics`

**Spec:** `docs/superpowers/specs/2026-08-13-backend-design.md`

## Global Constraints

- All services must stay within free tier limits (Supabase: 500 MB DB, 50k MAU; Resend: 3k emails/month; Vercel: 100 GB bandwidth)
- Never expose `SUPABASE_SERVICE_ROLE_KEY` to the browser — server-only, never prefixed `NEXT_PUBLIC_`
- All Supabase tables must have Row Level Security enabled
- `@supabase/ssr` cookie session pattern must be used — never `@supabase/supabase-js` direct in server components
- Existing `CoupleSite.tsx` presentation logic must not change (only the RSVP section is new)
- `src/lib/data/storage.ts` exported `storage` binding must remain a `StateStorage` — all three Zustand stores pick it up automatically
- Brand email: `hello@marram.studio` (studio inbox); sending domain: `marram.studio`

import { createServerClient as createSSRServerClient } from "@supabase/ssr";
import { cookies } from "next/headers";

export async function createServerClient() {
  const cookieStore = await cookies();
  return createSSRServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() { return cookieStore.getAll(); },
        setAll(cookiesToSet) {
          try {
            cookiesToSet.forEach(({ name, value, options }) =>
              cookieStore.set(name, value, options),
            );
          } catch {}
        },
      },
    },
  );
}

export async function createServiceClient() {
  const cookieStore = await cookies();
  return createSSRServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.SUPABASE_SERVICE_ROLE_KEY!,
    {
      cookies: {
        getAll() { return cookieStore.getAll(); },
        setAll(cookiesToSet) {
          try {
            cookiesToSet.forEach(({ name, value, options }) =>
              cookieStore.set(name, value, options),
            );
          } catch {}
        },
      },
      auth: { autoRefreshToken: false, persistSession: false },
    },
  );
}

- [ ] **Step 1: Create middleware**

`src/middleware.ts` — uses inline `createServerClient` (middleware can't use the `cookies()` API from `next/headers`):
```ts
import { createServerClient } from "@supabase/ssr";
import { NextResponse, type NextRequest } from "next/server";

export async function middleware(request: NextRequest) {
  let supabaseResponse = NextResponse.next({ request });

  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() { return request.cookies.getAll(); },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value }) =>
            request.cookies.set(name, value),
          );
          supabaseResponse = NextResponse.next({ request });
          cookiesToSet.forEach(({ name, value, options }) =>
            supabaseResponse.cookies.set(name, value, options),
          );
        },
      },
    },
  );

  const { data: { user } } = await supabase.auth.getUser();

  const { pathname } = request.nextUrl;
  if (!user && pathname.startsWith("/dashboard")) {
    const loginUrl = request.nextUrl.clone();
    loginUrl.pathname = "/login";
    loginUrl.searchParams.set("next", pathname);
    return NextResponse.redirect(loginUrl);
  }

  return supabaseResponse;
}

export const config = {
  matcher: [
    "/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)",
  ],
};
```

- [ ] **Step 2: Create OAuth callback route**

`src/app/auth/callback/route.ts`:
```ts
import { NextResponse } from "next/server";
import { createServerClient } from "@/lib/supabase/server";

export async function GET(request: Request) {
  const { searchParams, origin } = new URL(request.url);
  const code = searchParams.get("code");
  const next = searchParams.get("next") ?? "/dashboard";

  if (code) {
    const supabase = await createServerClient();
    const { error } = await supabase.auth.exchangeCodeForSession(code);
    if (!error) {
      return NextResponse.redirect(`${origin}${next}`);
    }
  }

  return NextResponse.redirect(`${origin}/login?error=auth`);
}
```
